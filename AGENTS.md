# Project guidance

## Orientation

Read [docs/architecture.md](docs/architecture.md) for module boundaries and [docs/compatibility.md](docs/compatibility.md) for the tested syntax scope. Runtime versions and commands are defined in `package.json`; Kotlin is pinned in `gradle/libs.versions.toml`, and Gradle by the Wrapper. Do not introduce a separate mise configuration.

## Parser and generated sources

- Official reference sources are in `kotlin-parser/upstream/`, identified by `kotlin-parser/upstream/metadata.json`. Portable code is in `kotlin-parser/src/commonMain/`; the official compiler dependency belongs only to `jvmTest`.
- Keep grammar changes easy to compare with the official parsing flow. Follow [docs/upstream-upgrade.md](docs/upstream-upgrade.md) when changing the syntax target.
- `LexerTables.kt` and `LexerActions.kt` are generated by `pnpm generate`. Change the generator or upstream input instead of editing their generated output.
- Kotlin-generated WASM glue keeps its `.mjs` extension. Handwritten TypeScript imports include `.ts`; use syntax supported by the existing native-TypeScript configuration.

## Verification and evidence

Use [docs/testing.md](docs/testing.md) to select checks for the changed surface. Parser changes require official differential and JVM/WASM checks; WASM/Worker/provider changes also require extension checks. Build before typechecking on a clean checkout because generated assets supply types.

`build/` and `dist/` are generated outputs. Benchmark scripts default to `build/benchmarks/`; archived JSON under `benchmarks/reports/` is historical evidence, not a baseline to overwrite during routine runs. Record whether tests ran freshly or used Gradle's up-to-date results, and do not present low-sample smoke runs as performance conclusions.
